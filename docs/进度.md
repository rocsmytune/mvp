### 1. 项目骨架

- 冒烟测试通过，整栈 curl 验证

### 2. 本地登录 + 鉴权
- 接口：`POST /api/auth/login`、`GET /api/auth/me`
- 认证：bcrypt 密码哈希 + JWT（HS256）；业务侧统一依赖 `get_current_user`
- 权限：`permissions.py` 仅角色常量（具体校验待各写接口接入时实现）
- 种子：`backend/seed.py`（3 个构造账号）
- 前端：登录页（工号+密码，SSO 入口预留），token 存 localStorage，axios 拦截器自动附带
- 测试：6 个登录用例通过

### 3. 设备/部件 CRUD + ChangeLog
- 接口：`/api/assets`、`/api/components` 增删改查（一律软删除，查询默认过滤）
- 权限：`permissions.py` 落成真校验（admin 全权 / 柜主仅自己机柜 / 成员只读）
- U 位校验：服务层友好报错（范围 1–45、乱序、重叠 409）+ 数据库排除约束兜底
- ChangeLog：所有写操作走 `services/`，自动记录 create / update（按字段）/ delete
- 字段来源：cpu_model/sn/ip_inband/bmc_ip 记录 source；manual 不被 import 覆盖（已实现并测试）
- 种子：演示机房 TEST-01 + 机柜 A01-01（归柜主甲）/ A01-02（归管理员）
- 测试：20 个用例通过（三角色权限、U 位重叠/越界/乱序/缺 U、ChangeLog、字段来源保护）

### 4. 机房/机柜管理 CRUD
- 接口：`/api/rooms`、`/api/cabinets` 增删改查 + `POST /api/cabinets/assign-owner` 批量指派柜主
- 权限：写操作仅 admin（`require_admin`）；读操作所有角色可看
- 校验：机房编码唯一、机柜(机房,名称)唯一、柜主必须是 cabinet_owner 角色
- 删除保护：机房内有柜 / 机柜内有设备时拒绝删除（409）
- 机柜列表带 `owner_name`/`room_code`（模型加 owner/room 关系，纯 ORM 层无迁移）
- 测试：32 个用例通过（新增 12 个：三角色权限、唯一性、指派校验、删除保护、ChangeLog、批量指派、读权限）

### 5. 前端 - 机房总览页
- 后端新增 `GET /api/overview` 聚合接口（已上架/待整理数量 + 机房列表 + 机柜及设备数/占用U）
- 前端重构：登录页抽离 `pages/LoginPage.tsx`、登录态外壳（顶栏：用户名/角色/退出）
- 机房总览 `pages/OverviewPage.tsx`：统计卡（已上架/待整理/设备总数/机柜总数）+ 按机房/区域筛选 + 机柜网格（名称/柜主/设备数/U位使用率进度条）
- 类型对齐后端 `api/types.ts`，`npm run build` 通过；未引入新依赖
- 测试：33 个用例通过（新增 overview 聚合统计用例；顺带修复池设备测试残留的清理）

### 6. 导入模块 - 方向确定 + 模型变更（增量1）
- 确定导入方向：**手工物料表格导入为主力**；computinglab 标准导入预留、暂不开发
- 表格 8 列：BMC IP / 整机SN / 物料类型 / SN / 物料编码 / 物料名称 / 备注 / 挂账人
- 定位：BMC IP → 资产 → 机柜 → U位；整机SN 二次确认，不符警告；找不到 → 预览报错提示先补录
- 权限：管理员导全部、柜主只能导自己机柜、成员不能导
- 挂账人：部件 + 交换机落库（拆工号关联 users）；服务器整机不挂账
- 数据模型：components 加 name/material_code/holder_id/holder_name；assets 加 holder_id/holder_name（仅交换机用）
- 迁移 0002 已应用；33 测试通过
