#### D1. 导入挂账人解析增强

- **现状**：挂账人仅支持「工号 姓名」（空格分隔）或纯工号。`importer/parse.py::parse_holder` 用 `split(None,1)` 拆首个空白；`services/component.py::_resolve_holder` 用正则 `^(\d+)(?:\s+(.+))?$`；`importer/resolve.py::_resolve_holder` 按工号查 users。
- **目标**：一栏同时支持
  - `00886677石铭哲`（工号+姓名，无空格）
  - `石铭哲00886677`（姓名+工号，无空格）
  - `石铭哲 00886677`（姓名 空格 工号）
  - `00886677 石铭哲`（工号 空格 姓名，现状已支持）
  - 纯 `00886677`（只有工号）→ 按工号匹配用户
  - 纯 `石铭哲`（只有姓名）→ 按姓名匹配用户
- **实现**：新写/改造统一的 `parse_holder(raw)`，按「数字/非数字」识别工号与姓名及其顺序：① `^(\d+)\s*(\D+)$` 工号在前；② `^(\D+)\s*(\d+)$` 姓名在前；③ 纯数字=工号；④ 纯非数字=姓名。`parse.py` / `resolve.py` / `component.py` 三处统一复用同一套解析+匹配。匹配：工号命中 users → 关联并快照姓名；仅姓名 → `User.name == name` 查询，唯一命中则关联，多命中/不命中 → 保留原文 + 警告（不硬拒绝）。
- **测试**：6 种输入 × 命中/不命中/同名多人的用例。
- **已定（2026-10-09）**：① 纯姓名匹配到多个同名用户 → 警告 + 存原文、不关联；②「工号+姓名」都给但姓名与库中不符 → 以工号为准 + 警告。

### E. 物料部件 SN 唯一性 / 相同 SN 导入确认 / 所在服务器直接修改（新增计划）

> 三件事：①部件 SN 是否强制唯一；②导入相同 SN 的确认语义补齐边界；③物料页可直接改「所在服务器」。

#### E1. 部件 SN 是否唯一（决策 + 检查）

- **现状**：`components.sn` 无唯一约束（仅普通索引 `idx_components_sn`），CLAUDE.md 规则9「部件 SN 重复只提示冲突、不硬性拒绝」。同一 SN 可并存多条（同型号多块硬盘无独立 SN、重复录入等），无 SN 部件（`sn IS NULL`）另计。
- **待检查/决策**：
  1. 是否对「有 SN 的部件」强制唯一？若强制，需加部分唯一索引（`deleted_at IS NULL` + `sn`），并在创建/导入重复时返回友好错误；
  2. 还是维持「允许重复 + 冲突提示」？若维持，需明确提示出现在哪（手动创建 / 导入预览 / 编辑），避免静默产生重复；
  3. 无 SN 部件不受唯一约束影响（`NULL` 不参与唯一）。
- **建议**：MVP 维持「不硬拒绝」，但手动创建与导入预览中显式标注「SN 已存在 N 条」，由操作人确认；后续再评估是否升级为强唯一。

#### E2. 导入相同 SN 的确认（检查）

- **现状**：已实现「SN 相同 → 打印字段级变动点 → 二次确认后落库（含跨机柜移动）」（§9 / D 节）。表格是权威来源，import 可覆盖。
- **待检查/补齐的边界语义**：
  1. 相同 SN 且字段完全一致（重复导入）→ 跳过（无变化）还是仍要求二次确认？
  2. 相同 SN 但物料类型（category）不一致 → 视为冲突警告还是允许覆盖？
  3. 相同 SN 但挂账人 / 所在服务器变化 → 是否计入变动点并提示？
  4. 同批文件内 SN 重复（同一行重复 / 多行同 SN）→ 去重语义（取首行 / 合并 / 报错）？
- **建议**：保留现有「二次确认」框架，把上述 4 类边界补成明确语义 + 对应测试（`test_import_resolve.py` / `test_import_api.py`）。

#### E3. 设备/物料页直接修改「所在服务器」

> ✅ 已完成（2026-10-09）：后端 `ComponentUpdate` 增 `asset_id` + `update_component` 跨设备迁移（校验目标设备存在、原/目标机柜权限、ChangeLog 记 `asset_id` 前后值）；前端物料 Tab「所在整机」编辑入口（远程搜索服务器）一并纳入「编辑部件」弹窗；列表行按 `cabinet_owner_id` 判定可编辑（管理员全权 / 柜主仅自己机柜）。见 §26。

- **现状**：物料 Tab「所在整机」只读；`ComponentUpdate` 不含 `asset_id`，改归属需回设备详情抽屉删除后重建。
- **目标**：物料列表「所在整机」列支持直接修改——下拉/搜索选择目标服务器（按 BMC IP / SN / 型号），一键把部件 `asset_id` 迁移到另一台服务器。
- **实现要点**：
  1. 后端：`ComponentUpdate` 增加 `asset_id`；`update_component` 处理跨设备迁移——校验目标设备存在、操作人需同时具备「原机柜 + 目标机柜」管理权限（跨柜移动两次 `ensure_can_manage_cabinet`），ChangeLog 记录 `asset_id` 前后值；
  2. 前端：物料 Tab「所在整机」列改为可编辑（AutoComplete 搜索服务器），保存调用 `updateComponent`，成功后刷新列表并提示；
  3. 权限：管理员全部；柜主仅能迁到自己机柜的设备；成员不可（后端强制，前端隐藏按钮只是体验优化）；
  4. 测试：跨设备迁移成功、目标设备不存在 404、跨柜无权限 403、ChangeLog 记录 `asset_id` 变更、软删部件不可迁。
